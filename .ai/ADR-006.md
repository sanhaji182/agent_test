# ADR-006 — Unify the Two LLM Client Layers (DL-2 Phase 2)

**Status:** Accepted (2026-07-28, owner: "Rekomendasi kamu saja" — proceed per recommendation)  
**Date:** 2026-07-28  
**Deciders:** Engineering owner  
**Supersedes:** None  
**Related:** TECHNICAL_DEBT DL-2, ADR-005 Phase 2 (approved origins), CHANGELOG 2026-07-28 "Align LLM provider routing" (Phase 1, commit 3b56bc9)

## Context

The codebase has two independent LLM client layers:

| | `internal/agent/llm_*.go` (execution layer) | `internal/ai/client.go` (planning layer) |
|---|---|---|
| Interface | `agent.LLM` — 6 domain methods (`AnalyzeCodebase`, `GenerateTestPlan`, `GenerateTestScripts`, `SuggestFixes`, `HealAction`, `HealActionWithVision`) | `ai.Client` — 1 generic method (`GenerateText`) |
| Implementations | `AnthropicLLM` (SDK), `OpenAILLM` (hand-rolled REST) | `AnthropicClient` (SDK), `OpenAICompatibleClient` (hand-rolled REST) |
| Consumers | `buildAgent()` (run execution), `handleTestAIProvider` (test connection), `cmd/mcp` | `aiClient()` → planning handlers (draft cases, feature extraction, failure analysis) |
| Vision support | Yes (`chatWithVision`, image_url content blocks) | No |
| Temperature | Hard-coded 0.2 in `OpenAILLM.chat` | `Config.Temperature` (default 0.2) |
| Max tokens | Anthropic path hard-codes; OpenAI path omits (provider default) | `Config.MaxTokens` (default 4096) |
| Error text | `"openai error (status %d): %s"` (includes body) | `"openai-compatible: status %d"` (no body) |
| Timeout | 2 min (both, since 2026-07-27) | 2 min (since 2026-07-27) |

**Phase 1 (done, 3b56bc9)** eliminated the *dangerous* divergence: provider-name normalization, accepted-provider sets, and per-provider default base URLs are now identical and regression-guarded by `TestProviderRoutingParity`. What remains is *duplicated transport code*: two hand-rolled `/chat/completions` POST implementations and two Anthropic SDK wrappers that drift in error detail, token limits, and capability (vision).

## Decision (proposed)

**Make `internal/ai` the single transport layer. Rebuild `agent`'s LLM implementations as prompt-domain wrappers over `ai.Client`.**

Rationale:
- `ai.Client` is the smaller, cleaner surface (1 method). Transport belongs behind the narrowest interface.
- `agent` already imports `ai` (one-way, since Phase 1). The dependency direction is settled.
- The `agent.LLM` interface (6 domain methods) stays **unchanged** — consumers (`Agent`, `PlaywrightRunner`, `buildAgent`, `handleTestAIProvider`, `cmd/mcp`) never see the refactor.

### Target shape

```
internal/ai/
  client.go        — Client interface + factory (as today)
  anthropic.go     — AnthropicClient (moved out of client.go; gains vision)
  openai.go        — OpenAICompatibleClient (gains vision + richer errors)
                     Client interface grows ONE method:
                     GenerateWithImage(ctx, prompt, imageBase64 string) (string, error)

internal/agent/
  llm.go           — agent.LLM interface (unchanged)
  llm_prompts.go   — ALL prompt templates + JSON parsing (from llm_anthropic.go
                     + llm_openai.go, deduplicated — they are ~90% identical)
  llm_adapter.go   — promptLLM struct: implements agent.LLM by composing
                     prompts with an ai.Client; replaces AnthropicLLM + OpenAILLM
  llm_factory.go   — NewLLM delegates to ai.New, wraps in promptLLM
```

### Phased migration (each step independently shippable, gated by build + `-race` suite)

1. **Step A — vision in `ai`:** add `GenerateWithImage` to `ai.Client`; implement in both clients (Anthropic image block / OpenAI image_url block, lifted verbatim from `llm_anthropic.go:203` and `llm_openai.go:44-56`). Anthropic path also gains `MaxTokens` from config. Add unit tests with a stub HTTP server.
2. **Step B — extract prompts:** move the 6 prompt builders + `stripJSONMarkers`/response parsing from both `llm_*.go` files into `llm_prompts.go` as pure functions (`buildTestPlanPrompt(analysis, requirements) string`, `parseTestPlan(raw) (*TestPlan, error)`, …). Both existing structs call them. Pure move — no behavior change. Prompt-parity test: assert both implementations produce byte-identical prompts.
3. **Step C — adapter:** add `promptLLM{client ai.Client}` implementing `agent.LLM` via the prompt functions. Switch `NewLLM` to return it. Delete `AnthropicLLM`/`OpenAILLM` bodies (keep `stripJSONMarkers` if referenced elsewhere). `llm_factory_test.go` parity tests must still pass unchanged.
4. **Step D — cleanup:** delete dead transport code, update CODEMAP/ARCHITECTURE, mark DL-2 resolved.

### Behavior changes to accept (documented, all strict improvements)
- Planning layer gains nothing user-visible; execution layer error messages unify on the richer format (status + body).
- OpenAI execution path gains `max_tokens` (was: provider default, unbounded cost).
- `handleTestAIProvider` keeps working via the unchanged `agent.LLM` interface.

## Consequences

**Positive:** one transport to patch (timeouts, retries, redaction, streaming later); vision available to planning; ~250 lines deleted; DL-2 closed.  
**Negative:** `ai.Client` interface grows a vision method that planning callers won't use (acceptable: 2 implementations, both in-repo); prompt extraction (Step B) is the riskiest step — mitigated by the byte-identical prompt-parity test.  
**Explicitly out of scope:** streaming, retries, provider-specific token accounting — separate ADRs if needed.

## Verification plan
- Steps A/B: new unit tests (stub HTTP server for transport; prompt-parity for extraction).
- Step C: existing `llm_factory_test.go` + full `go test ./internal/... -race` must stay green with zero test edits (proof the `agent.LLM` contract held).
- Manual: `handleTestAIProvider` smoke against a real key before marking DL-2 resolved.
